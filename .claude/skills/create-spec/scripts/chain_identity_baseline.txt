# Chain-identity findings already on `main`.
#
# A row here is a DEBT RECORD, not an exemption: it says "known, ticketed, not a
# regression introduced by this PR". Fixing the spec is what removes the row.
# Adding a row for a NEW finding defeats the guard — fix it instead, unless two
# specs describe one network on purpose, and then say so next to the row. See
# check_chain_identity.sh.
#
# Format: <KIND> <INDEX> <interface> <internal_path, or - for none> [TEMPORARY]
#
#   UNSEPARATED   every identity check on that endpoint is answered the same way
#                 by a node of another catalogue chain (the guard prints which)
#   UNIDENTIFIED  no Fail-severity check on that endpoint compares a value
#
# A row the catalogue no longer produces is STALE and FAILS the guard — delete
# it. That is deliberate: a stale row would silently re-permit the finding if
# the fix were ever reverted, so the ledger cleans itself. The `TEMPORARY` token
# is the one exception, for a fix already in flight on another branch: a stale
# TEMPORARY row is reported loudly but does not fail.
#
# Established 2026-10-14 by running the guard against main at 1a12b8c (MAG-2850).
